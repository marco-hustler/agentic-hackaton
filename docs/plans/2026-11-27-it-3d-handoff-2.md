## 1. How to run

```bash
# backend (repo root) — keep idealo live OFF unless deliberately testing
IDEALO_LIVE_ENABLED=false .venv/bin/uvicorn cleanbreak.api.app:app --reload --port 8000 --app-dir src
# frontend
cd frontend && npx vite --port 5179 --strictPort     # proxies /api → 127.0.0.1:8000
# checks
cd frontend && npx tsc -b && npx oxlint src
.venv/bin/python -m pytest -q                         # 57 passing
```

Sign in with any email + non-empty password (demo auth, Marco's `auth/`).
Vite can hang at 100% CPU after long sessions: kill and restart it on the same port.

## 2. Product state (what the user sees)

1. **Login** → **World** (3D isometric neighbourhood) or **List** (Marco's `ProcessList`), switch in the header.
2. A process = a house. Free lots are clickable (`world/FreeLot.tsx`) and the bottom **+ New process** button opens the wizard. Processes are stored in SQLite (`/api/processes`, Marco).
3. Click a house → camera centres → "Enter house" → exterior shrinks, interior **pops in** (spring). One **personal room per person**, labelled **only with the person's name**, furnished in their colour (bed, rug, lamp, desk, plant). **No item crates in the rooms** — user explicitly asked for that.
4. Inside a house, top nav tabs: World · **Inventory** · **Split** · List & Export (disabled).
   - **Inventory**: minimal list — photo, name, price (+ search). Click an item → goes to Split and opens its detail. The user wants lists minimal.
   - **Split**: board based on a Stitch mockup the user pasted, adapted to real data. Wide diorama on top; three equal columns (person A · Contested/sold · person B) of **cards** (photo, name, price only; contested cards add You/Other/Sell one-tap locks); bottom **dock** with balance bar + gap, "X pays Y €", solver mode (Balanced / Less cash / Sell contested), "How it's calculated" modal (totals, fair shares, wishes met, fairness, smart buys, idealo replacement links).
   - **Item detail**: large **centred modal** (two columns: photo + idealo value + evidence | who gets it, priority sliders, condition/year/retained value). Edits re-run the solver instantly.
5. Every house edit is **saved per process** (debounced), "Saving… / Saved" shows in the house nav.

## 3. Architecture notes (non-obvious, keep these)

- **Canvas never resizes.** `.world-frame` (CSS-animated rect, `data-mode`/`data-tab`) defines where the scene lives; `world/CameraRig.tsx` clips `.world-stage` to it (`clip-path`) and shifts the projection with `camera.setViewOffset` every frame. Resizing the canvas caused a visible snap at the end of transitions. Interior zoom fits the frame: `min(w/7, h/3.8)`.
- **Motion**: `world/motion.ts` — under-damped spring (`POP`, `OUT`), used for houses, interior, pawns, plus lot. CSS `.pop-in` / `.pop-in-late` / `.fade-in` in `index.css` for DOM. User wants **every animation fast, fluid and "pop"**.
- **3D labels** are plain DOM moved each frame by `world/labels.ts` (`LabelProjector`), not drei `<Html>` (breaks under React 19 StrictMode).
- **House state**: `house/useHouseInventory.ts`
  - load `GET /api/processes/{id}/inventory` (first read seeds the 7 demo items from the idealo cache, 0 MCP calls),
  - edits → local state → debounced `POST /api/solve` (names = process participants) → debounced `PUT …/inventory`; pending save flushed on leaving the house and on `pagehide` (fetch keepalive),
  - condition/year/override edits → `POST /api/reapply-depreciation` (0 MCP calls), with a per-item sequence guard.
  - The split is **not stored**; it is recomputed from items + mode.
- **DB**: `src/cleanbreak/db/processes.py` — tables `processes` (Marco) and `process_inventories` (mode + `valued_items` JSON). `data/processes.db` is gitignored. Tests use `PROCESS_DB_FILE` via `tests/conftest.py`.
- **Solver is 2-party.** Names come from the process: `You` + first invitee (`participantNames`). Rooms 3–5 exist visually but get no items in the split.
- Synthetic pointer events in Chrome DevTools report halved `offsetX` (DPR quirk) — for R3F click tests use real clicks or dispatch `click` as `MouseEvent`.
